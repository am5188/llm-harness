# 研究与证据规范

本知识库的目标不是收集观点，而是建立一条可复核的大语言模型发展史。每一个时间点、人物、数字和因果判断都必须能够回到来源。

## 证据等级

- **A：一手来源**：原始论文、预印本、公司官方公告、监管文件、演讲/访谈原文、项目仓库或技术报告。
- **B：高质量二手来源**：学术综述、大学研究中心、专业媒体的调查报道、经过编辑审校的书籍。
- **C：线索来源**：博客、百科、社交媒体、搜索摘要。只能帮助定位，不作为关键事实的唯一依据。

关键事实至少需要一条 A 级来源；若一手资料不可得，须明确说明限制，并补充两条相互独立的 B 级来源。

## 每条时间线记录必须包含

1. 日期（注明是发表、预印本、发布、融资、公开演示还是产品上线）
2. 事件的准确描述
3. 直接影响
4. 与前后事件的关系（事实与推断分开）
5. 来源编号、URL、作者/机构、发布日期、访问日期
6. 证据等级与待核查事项

## 写作规则

- 不把搜索摘要当作证据；必须打开原文并记录具体章节、页码或段落。
- 不把“开源”笼统使用，区分 source-available、open-weight 与 OSI 意义上的开源。
- 不把相关性写成因果性；因果判断须有原文声明或多来源交叉验证。
- 数字保留单位、币种、时间范围和口径；不同来源数字冲突时并列记录。
- 对未确认的说法标记为“待核查”，不以确定语气写入课程正文。
- 记录访问日期；网页可能变化时保存 PDF、网页存档或本地摘录（遵守版权，仅保存必要引用）。

## 单条记录模板

```markdown
### YYYY-MM-DD｜事件名称

- **事件类型**：论文 / 预印本 / 公司公告 / 融资 / 产品 / 政策 / 开源权重
- **事实**：
- **影响**：
- **与时间线的关系**：事实：；解释：
- **证据**：[S-0001]（A）
- **原文定位**：章节、页码或段落摘录
- **待核查**：
```

## 版本管理

每次补充资料、修正日期或改变解释，都必须：

```bash
git add -A
git commit -m "说明本次事实或资料变更"
git push
```

提交信息应能让未来读者知道改了什么，不使用含糊的 `update`。
